# Coding agent guide

This guide applies repository-wide. Task specifications and agent handoffs are written in English; user-facing explanations may be Japanese. Read the [ADR index](docs/adr/README.md), then the relevant accepted decisions and their scoped supersessions.

## Product and authorization

**Latest accepted notes resource policy: [ADR 0023 / B02-R02 A](docs/adr/0023-configurable-finite-notes-resource-budgets.md).** Use explicit finite configurable defaults/limits for individual raw-note size, aggregate operation bytes/work and structural-proof traversal. At a limit, preserve independently admissible metadata/complete atomic units, withhold oversize/unproven bodies and unfinished units, and report the actual stop without truncation, false completeness, hidden durable staging or fake physical quarantine. Deliberately higher finite settings permit retry with actual original Capture/provenance and semantic keys; never rewrite facts/groups, weaken B02-R01 checks or delete already admitted bytes after a lower setting. No numeric defaults, precise accounting or operation/resume fences are selected. Next B02-R03 asks measurement/charging; exact notes grammar, B03 and GCTX-M10 remain open. No implementation or merge.

**Latest accepted note-body role evidence: [ADR 0022 / B02-R01 A](docs/adr/0022-receiver-verified-notes-role-admission.md).** Before retaining a note blob, require the receiver's checked captured-root/tree-to-target-to-note structure under supported notes semantics plus exact body format/OID/type/size/digest checks. A source report, trusted source, ref prefix, decoder or sender verified flag is insufficient. Preserve admissible metadata without durable unproven-body staging. Check only the needed mapping scope; no full enumeration, target-body acquisition, invented commit for a direct-tree root or mandatory live fetch. Structural proof does not authenticate ref freshness/origin or prove physical health now. Preserve immutable scoped evidence, semantic composite references, alternatives and existing admitted bytes. B02-R02 configurable finite budget policy is fixed by ADR 0023; B02-R03 resource measurement/charging is next; exact proof grammar, B03 and GCTX-M10 remain open. No implementation or merge.

**Latest accepted notes claim/group identity: [ADR 0021 / B01-R06 A](docs/adr/0021-direct-semantic-notes-claim-group-keys.md).** Use the actual Capture UUIDv4 pair, actual typed slot, asserted value and genuine original provenance directly as composite PK/FK components. Group identity includes the entire immutable membership, actual order and asserted scope; preserve atomic group visibility. Exact original-evidence replay deduplicates, independent evidence stays distinct, and conflict comparison uses the genuinely overlapping logical slot rather than PK inequality. No hash-only key, row surrogate, new per-claim UUID, fabricated unknown path/ordinal or provenance. Insufficient identity and inconsistent immutable evidence coordinates fail closed without rewriting facts. Receiver-local checks are separate evidence. B02-R01 structural role-evidence strength is fixed by ADR 0022; B02-R02 finite configurable budget policy is fixed by ADR 0023; B02-R03 measurement/charging is the next owner blocker; B03/GCTX-M10, exact DDL/wire/trust and resource contracts remain open. No implementation or merge.

**Latest accepted notes-member conflict policy: [ADR 0020 / B01-R05](docs/adr/0020-immutable-competing-notes-member-claims.md).** Preserve eligible genuinely attributed contradictory notes **reports** under the same Capture as separate immutable typed Git Core alternatives, deriving an explicit unresolved conflict rather than a time/source/arrival winner. No conflicting member insertion into a previously accepted GCTX-M03 atomic group or union into a complete list. Under GCTX-M04 only precisely relevant receiver-locally checked Git notes mapping may be preferred, retaining reports; verified note blob bytes alone do not establish target association. A conflicting issuer/repository/ref/root **Capture identity** is rejected, not an admissible member alternative. KEY-P01 prohibits storage-only claim/conflict surrogates; ADR 0021 / B01-R06 A fixes direct semantic composite claim/group keys and exact replay equality. B02-R01 body role-evidence strength is fixed by ADR 0022; exact proof grammar, B02-R02 configurable finite budget policy is fixed by ADR 0023; exact resource measurement/defaults, B03 completeness and GCTX-M10 remain open; metadata conflicts do not signal CAS physical corruption. Git Core stays INSERT-only and ordinary file bodies stay excluded.

**Latest accepted same-capture fact admission: [ADR 0019 / B01-R04](docs/adr/0019-monotonic-notes-capture-fact-admission.md).** Owner selected **A**: under an existing `(capture_origin_uuidv4,capture_uuidv4)`, append genuinely new compatible immutable source-attributed facts and separately atomic coherent relation groups; exact replays are idempotent and do not create a new Capture. Keep actual provenance and stable capture pair, no per-fragment surrogate or generic Publication. B03 still governs complete/partial/known-empty/unknown evidence; B02-R01 role-evidence strength is fixed by ADR 0022; B02-R02 configurable finite budget policy is fixed by ADR 0023; exact measurement/defaults, proof grammar and GCTX-M10 CAS-41 disposition remain open. No Core UPDATE/DELETE/REPLACE/GC.

**Latest accepted product scope: [ADR 0014 / GCTX-S01](docs/adr/0014-history-and-notes-catalog-without-file-archive.md).** `git-repo-db` is a Git history/structure/notes catalog, not a repository-file-content archive. ## Architecture and domain invariants

- **Four stores:** Git Core is authoritative for permanent repository identity, attributed Git metadata, history/structure/notes, actual observations and allowed retained metadata bytes. It is application-level INSERT-only: no UPDATE, DELETE, REPLACE, mutable progress/revision or in-place repair loopholes. Context independently owns durable PR/Issue/comment/review/Source/Provider state, its text/evidence/conflicts; it is not disposable. Context may reference Core, never the reverse for Core validity. Operational and Search remain reconstructible. Full Context-containing backup includes both authoritative stores and their consistency evidence; Git-only backup is labeled as such. Neither is a full file-content repository backup under ADR 0014.
- **Layering:** dependencies remain `cli -> application -> domain/ports`; adapters own SQLite, Git/HTTP and filesystem operations.
- **Schema:** `adapters/sqlite/schema.py` composes packaged production DDL, including generated JSON guards. Initializer, writers, readers, Exchange, maintenance and installed distributions use exact fingerprints. Fresh format only; no compatibility shim.
- **Connections:** enable foreign keys and recursive triggers. Use SQLite snapshots/savepoints and OS `locks/writer.lock`. Do not use immutable connections against mutable catalogs or hold a write transaction over network work. Roll back intended units on body/constraint/COMMIT failure.
- **Identity:** service, repository and Source-registration UUIDv4 are portable; local Source IDs differ. Names/URLs do not merge identities. Explicit equivalence/cancellation assertions do not rewrite facts or coverage. `repository_uuidv4` is permanent.
- **Time:** absolute times are signed int64 Unix epoch microseconds with `_us`. NULL means unknown; zero/negative values are valid. Receipt order, UUID order, processing time and parser version do not establish domain freshness.
- **Provider state:** PR attributes, natural-key title/body/conversation documents, independent threads and known Source roster retain latest accepted state with necessary current-field provenance. No normalized full API edit history. Missing differs from explicit null; inherited fields keep original clock/capture/module/version. Genuine equal/incomparable-clock alternatives stay unresolved.
- **Issue/review identity:** ordinary Issue identity is service/provider ID, independent of repository membership/number. Review identity is PR/kind/provider document ID. Transfers preserve capture. Detached captured IDs may survive Exchange without invented registrations; verify relationships when present. Receiver-local checks advance only on accepted authoritative live acquisition with pre-request revision/scope fences, never sender checks.
- **Documents:** use `(change_request_id, kind, provider_change_request_document_id)`. Exact UTF-8 SHA-256 identifies domain text. No document surrogate/version table or duplicate PR title/body authority.
- **Coverage:** exactly five claim columns and explicit typed ownership. Latest observation's candidate set determines complete/partial/unknown/conflict; no fallback to older complete. Details are advisory. Individual resources remain usable when a larger list fails. Empty terminal differs from no terminal; nested required-child and exact head/base evidence must be truthful. Metadata/notes inventory, allowed-body presence and file-content restorability are different scopes; no relabeling a stronger old completeness claim.
- **Source associations:** known positive pairs only. Partial inventory R1 cannot delete known R2. No new negative membership or deletion policy.
- **Context anchors:** retain actual provider events and minimal head/base/role anchors. Current head B cannot borrow A's assessment or require the whole old PR as provenance.
- **GCTX-M01–M03:** metadata-only Core needs no bytes/rehash/Context. Use one nominal full `(object_format, oid)` identity; neither identity nor shared references imply membership, actual bytes or canonical facts. Preserve potentially conflicting field-level claims and coherent observation-scoped ordered relation groups. Keep unknown/partial/known-empty distinct; do not union parent/tree groups, invent raw offsets/ordinals or update prior reports on later arrival.
- **Notes:** preserve explicit namespace/ref and observed root/capture association to an annotated target, note OID where known and annotation bytes/text with actual provenance. Notes are a blob role, not a new Git native type. Direct-tree notes refs, binary/empty notes, unknown targets, multiple namespaces and shared file/note OIDs need correct treatment. Do not apply note-body permission transitively to target files, collapse all notes onto target OID alone, strip/truncate exact content, or infer canonical notes mapping from a flag. Ref changes/removal do not erase old Core observations. Namespace discovery is fixed by ADR 0015 (all observable `refs/notes/*` plus explicitly nominated additional refs). Capture identity B01-R02/B01-R03 and monotonic fact admission B01-R04 are fixed by ADR 0016/0018/0019; B01-R05 competing member report preservation is fixed by ADR 0020; B01-R06 direct semantic claim/group keys and replay equality are fixed by ADR 0021; B02-R01 structural role-evidence strength is fixed by ADR 0022; B02-R02 configurable finite budget policy is fixed by ADR 0023; exact measurement/defaults, B03 completeness and exact notes proof grammar remain open.
- **GCTX-M04–M06:** retain explicit decoder provenance, canonical verified values only for actually checked fields, conflicting reports and historical admission evidence. For allowed exact metadata/notes representations, check Git format/OID/type/size and physical digest, install intrinsic structure atomically and retain bounded immutable proof. An earlier unverified type/size/parent claim cannot poison later valid bytes. No preferred decoder, generic success ledger or sender-verification laundering. Core owns Git checks/evidence; Context owns Provider assessment; Operational owns Jobs.
- **GCTX-M07–M09:** metadata-only and historical canonical reads require no mandatory raw-body rehash. Verified allowed-body output must check the same selected/emitted bytes in a coherent scope; old admission/scan does not prove healthy-now. Retain damaged instance I1 and its durable diagnosis; add independently validated I2 and narrow recovery facts without byte overwrite or trigger bypass. Derive eligible-to-check candidates from immutable instance evidence and use stable non-authoritative local key ordering; verify actual output. A new fault must be durably accounted for before safe retry; do not hide failed fault recording. Healthy I2 does not clear I1 or lower physical quarantine counts automatically. GCTX-M10 quarantine disposition/count and precise physical layout/read-fence protocols remain unresolved.
- **Transport:** no required API originals/replay. Normalize accepted partial GraphQL requirements/continuations/targets in memory. Reject opaque Provider replicas and hidden original-bearing pending/job JSON. Optional external recording/warning failures are nonfatal with bounded allowlisted diagnostics.
- **Body retention/CAS:** ordinary file-body archival is excluded by ADR 0014. The internal retained-metadata store accepts only allowed commit/tree/tag representations and evidenced notes bodies; Context text belongs in Context. Preserve exact bytes, collision defenses and CAS-41 for actual retained instances. Copied-database active physical quarantine count is verified before restore diagnosis, not replaced by an event count. Never classify intended nonacquisition as corruption or actual retained-byte loss as optional absence. Restore to a fresh stage and publish atomically without overwrite. No physical retained-data cleanup or new Core GC.
- **Exchange:** resolve typed resources/dependencies from a consistent snapshot. Envelopes/idempotency records do not own domain validity. Preserve genuine missing/conflicting candidates, reverse/repeat/late promotion/onward export without invented closure or provider authenticity. Validate retention purpose before accepting body-bearing entries; don't reintroduce ordinary file contents through staging or decoded text. Metadata-only exchange never needs fake payloads; sender checks are not local authority.
- **Revision:** implemented `local_revision` is the receiver-local counter and `advance_local_revision` replaced mechanical publication. The target must replace this mutable Core counter with an append-only-safe/fenced design. No counter-history table or sender-revision freshness import.
- **Jobs/caches:** freeze Source registrations and nonsecret settings. Resolve credential references at resume. Operational/cache loss cannot invalidate admitted facts. For allowed body-dependent work, require genuine safe fetch or reuse-unavailable, not a fabricated observation; ordinary metadata queries never hydrate content. No long-lived hidden file archive.

LFS objects and ordinary LFS pointer file bodies are outside new file archival; genuine supplied LFS/attachment metadata and existing Context evidence keep their meaning. Automatic external body fetching, broader deletion propagation, transport archive retention and CAS-76/CAS-77 remain deferred. Context-only GC-01/GC-02 remain; GC-03/GC-04 are not decided and never apply to accepted Git Core facts.

## Implementation, review and acceptance

For substantial architectural changes, fix owner decisions in a focused ADR/design PR, then implement coherent stacked PRs only when authorized. Independent subagents and executable counterexamples are permitted. The four-scope review requirement applies to the large Schema 20 redesign and tasks explicitly requiring it, not automatically to a prose fix. Reviewers must not approve their own production changes. Fix root causes, add regressions and re-review material findings.

**Development versus release:** run risk-relevant focused local tests, expanding by dependency and correctness risk rather than demanding full suites after every edit/PR. Ordinary development CI uses inexpensive static/lint/format/configuration checks and smoke tests, inspecting local evidence and reporting gaps without automatically duplicating a full locally verified suite. A green development run means selected checks passed, not full runtime acceptance. Only explicit user-invoked release validation requires full independent pytest locally AND hosted CI, isolated wheel/sdist packaging, schema/integrity checks and exact test-node reconciliation. Release validation itself authorizes no release, deployment, tag or merge. Preserve meaningful behavior tests; retire obsolete mechanism assertions only with explicit replacement-node mapping. Report versions, failures, skips, exclusions and unexecuted tests.

Use one controlled workload at a time for comparable timing; concurrent timings are not sequential benchmark evidence. Keep historical reports, update active docs for changed behavior, and submit real dependencies/findings. Named merges require authorization and independent integration-ancestry/effective-tree verification. ADR 0014 does not authorize any implementation, real-catalog extraction or data deletion.

## Reuse lessons as repository Agent Skills

Repository-local skills live in `.agents/skills/<skill-name>/SKILL.md`, with YAML name/description and optional neighboring references/scripts. Discover/read only relevant skills at task start. Agents without discovery should inspect that directory. Skills are reusable procedures, not policy changes or execution permissions.

Actively capture a verified generalizable lesson from repeated root-cause failures, non-obvious independent-review findings or hard-won reliable procedures. Prefer improving an existing skill rather than overlapping skills. At stable checkpoints and handoff, use `$lessons-to-skills` to assess symptoms, root cause, verified fix, reproduction/check commands, applicability, counterexamples and source links. Favor deterministic helpers. Avoid speculative recipes, one-off logs, unverified PASS claims, private data/credentials and converting open architecture choices into skill rules.

When authorized to edit the task branch, commit applicable skill updates with their correction or a dependent documentation PR. A read-only reviewer may recommend but not mutate the reviewed tree. Validate frontmatter, links and helpers; include skills in review/handoff. Do not create placeholders if no reusable verified lesson exists. See `docs/change-aware-ci.md` and the existing repo-local skills practice for CI selection. Proposed governance PR #52 does not automatically authorize wholesale ADR retirement.

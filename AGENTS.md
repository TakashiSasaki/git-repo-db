# Coding agent guide

This guide applies repository-wide. Coding-agent task specifications and handoffs are written in English; user-facing explanations may be Japanese.

## Product and authorization

Catalog3 schema 18 is the sole runtime for fresh initialization, source discovery, Git/GitHub acquisition, scoped current state and retained immutable parsing histories, offline queries/search, portable repository exchange and maintenance. The application is unreleased and has one developer. No old database, internal API, CLI or migration compatibility is required. The v2 salvage importer and its workspace have been retired under the October 2026 integration task. Historical reports are evidence, not acceptance gates.

Preserve existing Git history and uncommitted work. Commits and stacked PRs are permitted when authorized by the active task. Never merge or release without authorization. Use disposable synthetic data; never commit real databases, caches, raw authenticated traffic, credentials or private repository content. Stateful synthetic commands require an explicit disposable `--state-dir`. No implicit acquisition, live-source testing or retained-data mutation.

## Transport-independent implementation boundary

The [transport-independent core ADR](docs/transport-independent-core-adr.md) remains the accepted target. Schema 18 preserves transport-independent current Issue/review acquisition, admission, field evidence, collection receipts, ordinary readers, exchange and maintenance with actual parser module/version attribution; no profile/certificate/trust/selection dependency applies to these rows. See [implementation and blockers](docs/transport-independent-core-implementation.md). Historical PR, independent thread, Source inventory and Git parser publication/selection remain the existing baseline: their replacement domain publication, lifecycle, completeness and field contracts are deferred. Do not invent replacements or claim full ADR implementation.

The [Phase 1 retirement decision](docs/phase1-api-original-retirement.md) supersedes older API-original preservation requirements only within R1–R7. Retrospective API parsing, including external `reparse-message` projections, and the current-resource `replay` admission mode are retired. `parser reparse` accepts only retained Git acquisitions; bounded `inspect-message` remains a diagnostic reader. Fully rejected API responses have no core raw-byte admission staging or parsing-gap record. Accepted partial GraphQL roots, including envelopes with errors, remain historical publication/restart inputs at the documented Phase-2 boundary; optional external transport recording is separate. Shared CAS admission requires an explicit representation; retained Git bytes and accepted historical API publication/proof paths keep their separate meanings and common integrity checks. See the [implementation inventory and remaining boundaries](docs/phase1-api-original-retirement-implementation.md); provider JSON projections remain pending the field-inventory decision.

## Current-state and transport contracts

Ordinary Issues and their comments share one physical current-state table. Reviews and review comments share a second current-state table. Keep every distinct resource at its latest accepted state; ordinary Issue retention does not apply to PR conversation comments. Issue identity is service plus provider Issue ID, independent of current repository membership/number. Review logical identity remains change request plus kind plus provider document ID. Provider clocks are endpoint-specific evidence, not total-order clocks; incomparable conflicting updates remain visible and cannot produce an undisputed current winner.

Each current row's `field_evidence_json` attributes only retained current values and metadata paths. Omitted fields retain their original clock/capture/parser module/version; an older complete response may fill unknown fields without replacing newer known values. Keep genuine equal-clock contradictions unresolved. Current Issue/comment membership is separate from the original acquisition snapshot: transfer changes repository/binding/number while retaining captured endpoint, Source and times. Detached captured identifiers may survive exchange without importing the old repository/Source registration; validate existing captured relationships when present. `last_checked_at_us` is receiver-local and advances only for accepted authoritative live acquisition with the pre-request revision/scope fence, never from sender checks; current-resource replay admission is retired.

The transport boundary and recording adapters own supplementary message recording and archive reading. Recording is optional for current-state resources. Domain bodies, typed owners, per-field parser module/version attribution and collection-completeness evidence remain durable without supplementary archive access. PR/Git immutable inputs and independent thread contracts retain their required evidence. Never seal a mutable row as an immutable parser output. Preserve minimal stable code/review-target references rather than retaining normalized review edit histories.

Recorder callback and warning-output failures remain nonfatal to valid acquisition. Sanitize recorder codes through the bounded allowlist and retain only the latest 100 transport diagnostics; cancellation, transport, parser and catalog failures retain their ordinary behavior.

CAS-41 is selected: backup manifests require the verified copied database's active physical `payload_quarantine` count, strictly checked before restore diagnosis. D2 is retired/not applicable; fabricated identity remains prohibited. LFS collection preserves Git pointer bytes; attachments preserve source text/URLs. Body acquisition, automatic external URL fetching, transport archive retention/deletion, broad deletion propagation and CAS-76/CAS-77 remain deferred.

## Architecture and immutable contracts

- Dependencies remain `cli -> application -> domain/ports`; adapters own SQLite, Git/HTTP and filesystem operations.
- Packaged production DDL is composed by `adapters/sqlite/schema.py`. Initializer, writers, readers, exchange and maintenance use the same complete DDL and fingerprint.
- Enable foreign keys and recursive triggers on every connection. Use ordinary SQLite snapshot/transaction semantics and the OS `locks/writer.lock`; never immutable connections against a mutable catalog.
- Service, repository and Source registration UUIDv4 are portable identity. Local Source IDs are separate. URLs/names never merge identity; explicit equivalence assertions do not rewrite facts or coverage.
- Persist signed int64 Unix epoch microseconds with `_us` suffixes. Null is unknown; zero and negative values are valid.
- Preserve coverage v2: exactly five claim columns and explicit ownership. Latest observation time determines the set of candidate states, including unknown; no fabricated remote claims or completion.
- Documents use `(change_request_id, kind, provider_change_request_document_id)`. Exact UTF-8 text SHA-256 identifies text bodies. No document surrogate/version table or mutable parser metadata in shared identity rows.
- For retained immutable interpretations, retrieval UUIDs and parsed-result UUIDs are distinct. Results have one repository or Source owner, typed owned inputs, direct generated-fact foreign keys and sealed immutable input/output membership. Current Issue/review resources use the scoped module/version attribution contracts above and never require a parser profile.
- Remaining historical parser definitions include implementation, settings, output schema and all supported capabilities. Passed verification covers the entire definition. Specific verification evidence, invalidation and receiver-local trust remain distinct. No version-label-only identity or implicit profile upgrade.
- Remaining historical fact selection and parser/profile selection derive from immutable predecessor DAGs. Missing dependencies and forks remain unresolved, independent of timestamps, UUID ordering or receipt order. A conflicted child scope cannot inherit its parent selection. Mutable resource admission follows proven provider ordering or serialized live context, with incomparable candidates staged as conflict.
- Physical bytes are keyed by SHA-256 BLOB32; logical payloads by `(representation,sha256)`. Hash admission and exact-byte comparison are mandatory. `unresolved_payloads` contains only five-column physical-corruption diagnostics; rejected-payload staging accepts only raw Git content. Explicit atomic repair requires a real `git_object_payloads` reference and replacement validation against every mapped Git object's format/OID/type/size; a physical digest shared with API content remains eligible through that Git reference. Full scans, quarantine, backup and restore continue to protect all physical bytes.
- Exchange is one repository with required owners, acquisition context and bytes. Original-only export/import/promotion is retired; retained historical domain facts and exact collection/304 proofs may still require original inputs. Keep `--fetch`/`--collection` selectors for those actual domain/proof closures. Exclude all Source-wide inventory evidence, receiver-local trust/quarantine and operational validator caches. Preserve unknown dependencies and conflicts durably without blocking independent valid records.
- Backup verifies source and copied bytes and records active physical quarantine count; restore checks the count before diagnosis and uses a fresh retained stage and atomic no-overwrite publication. Known quarantined bytes are retained with their diagnostics.
- Job plans fix Source registrations and non-secret acquisition settings at creation. Resume restores the plan and resolves credential references at execution. CAS-76/CAS-77 remain deferred.

## Verification and evidence

Use one practical Python/SQLite environment and report actual versions. Run focused tests during integration, then the complete ordinary suite, fresh DDL/FK/integrity checks, lint/format and isolated wheel/sdist installs. Test counts are evidence rather than targets. Retired migration-only cases are documented separately from current-contract replacements. Preserve meaningful behavioral tests and disclose failures, skips and unexecuted checks separately.

The built-in parser verification artifact binds exact implementation hashes to capability test evidence. Regenerate it only from successful relevant tests; final acceptance runs without test bootstrap overrides. Hosted acceptance must correspond to the submitted final HEAD.

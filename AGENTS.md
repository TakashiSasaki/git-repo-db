# Coding agent guide

This guide applies repository-wide. Coding-agent task specifications and handoffs are written in English; user-facing explanations may be Japanese.

## Product and authorization

Catalog3 schema 19 is the sole runtime for fresh initialization, source discovery, Git/GitHub acquisition, scoped current state and retained immutable parsing histories, offline queries/search, portable repository exchange and maintenance. The application is unreleased and has one developer. No old database, internal API, CLI or migration compatibility is required. The v2 salvage importer and its workspace have been retired under the October 2026 integration task. Historical reports are evidence, not acceptance gates.

Preserve existing Git history and uncommitted work. Commits and stacked PRs are permitted when authorized by the active task. Never merge or release without authorization. Use disposable synthetic data; never commit real databases, caches, raw authenticated traffic, credentials or private repository content. Stateful synthetic commands require an explicit disposable `--state-dir`. No implicit acquisition, live-source testing or retained-data mutation.

## Decision authority and change boundaries

Apply instructions in this order when planning or reviewing changes:

1. **Explicit owner decisions and permissions for the active task**, within their stated scope. A new decision supersedes an older one only where the owner explicitly changes it; approval to merge one PR stack does not authorize merging another.
2. **Accepted ADRs and explicit scoped supersession decisions**, reading the latest accepted decision for each topic. Never reopen repository identity, epoch microseconds, coverage v2 or other settled contracts merely for implementation convenience.
3. **Current production schema and runtime contracts** for behavior not superseded by an authorized redesign. Such behavior must remain correct until its replacement is implemented and verified; it is not automatically the desired final design.
4. **Historical reports, snapshots and validation receipts** as evidence of prior work, not as current requirements or acceptance gates.

Separate **accepted target design**, **implemented behavior**, and **deferred choices** in every architectural change. A previously authored ADR's "not implemented" status describes its original checkpoint unless updated; consult the current schema, implementation handoff and later PRs to determine actual progress. Report contradictions or missing decisions explicitly. Do not silently invent domain lifecycles, historical current-winner rules, collection proofs, parser-profile authority, retention policies or exchange trust rules.

The [transport-independent core ADR](docs/transport-independent-core-adr.md) establishes that API transport originals are not mandatory core inputs, only actual parser module name/version is required provenance, and parser-profile verification/selection DAGs are not part of the **target** architecture. The [Phase 1 decision](docs/phase1-api-original-retirement.md) retires standalone original-dependent functions R1–R7; it does **not** assert that all historical acquisition/proof paths already stopped saving API originals. Preserve legitimate domain content and correctness guarantees while replacing those paths.

## Design-to-implementation workflow

For substantial architectural changes, follow this default sequence:

1. **Investigate and decide.** Check latest main and packaged DDL, trace actual callers/dependencies, distinguish settled requirements from unresolved decisions, and document approved choices, superseded rules and explicit deferrals in a focused documentation/ADR PR.
2. **Implement in coherent large strides.** Stack implementation PRs on the design PR (or previous implementation PR), with explicit base/head dependencies. Prefer an integrated, testable unit over arbitrarily small changes. Implement independently settled parts even if another part needs a later design decision. Backward compatibility and intermediate working states are not requirements in this pre-release project.
3. **Review independently.** Use parallel or independent subagents, separate worktrees or disjoint tasks where useful. Reproduce adversarial counterexamples and review the integrated tree, including DDL, writers, readers, queries, exchange, maintenance and packaging.
4. **Validate exact revisions.** Run focused and complete applicable tests, fresh schema/FK/integrity/JSON checks, lint/format and isolated installed packages. Record actual tested feature SHA and tree, hosted CI, failures, exclusions and unexecuted tests. Historical passing receipts never substitute for final acceptance.
5. **Merge only when explicitly authorized for this stack.** Review and merge in dependency order; retarget each downstream PR to updated main, inspect its effective diff and revalidate any changed tested tree. Verify final main after integration. Merge authorization never implies release or deployment authorization.

Ordinary bug fixes that do not change settled architecture may use a direct corrective PR. Never create a new policy simply to make a test pass. Keep PR handoffs factual about implemented, partially implemented and blocked work; preserve meaningful tests rather than deleting surviving behavioral coverage.

See [implementation and blockers](docs/transport-independent-core-implementation.md). Historical PR, independent thread, Source inventory and Git parser publication/selection remain the existing baseline: their replacement domain publication, lifecycle, completeness and field contracts are deferred. Fully rejected API responses have no core raw-byte admission staging or parsing-gap record. Accepted partial GraphQL roots, including envelopes with errors, remain historical publication/restart inputs at the documented Phase-2 boundary; optional external transport recording is separate. Shared CAS admission requires an explicit representation; retained Git bytes and accepted historical API publication/proof paths keep their separate meanings and common integrity checks. ## Active schema 19: current resources and transport contracts

The following are **as-implemented requirements for existing paths**, not new permanent decisions about resource lifecycles or historical observation selection. Preserve them while those paths remain active; an accepted later ADR may replace them with independently validated behavior.

Ordinary Issues and their comments share one physical current-state table. Reviews and review comments share a second current-state table. Keep every distinct resource at its latest accepted state; ordinary Issue retention does not apply to PR conversation comments. Issue identity is service plus provider Issue ID, independent of current repository membership/number. Review logical identity remains change request plus kind plus provider document ID. Provider clocks are endpoint-specific evidence, not total-order clocks; incomparable conflicting updates remain visible and cannot produce an undisputed current winner.

Each current row's `field_evidence_json` attributes only retained current values and metadata paths. Omitted fields retain their original clock/capture/parser module/version; an older complete response may fill unknown fields without replacing newer known values. Keep genuine equal-clock contradictions unresolved. Current Issue/comment membership is separate from the original acquisition snapshot: transfer changes repository/binding/number while retaining captured endpoint, Source and times. Detached captured identifiers may survive exchange without importing the old repository/Source registration; validate existing captured relationships when present. `last_checked_at_us` is receiver-local and advances only for accepted authoritative live acquisition with the pre-request revision/scope fence, never from sender checks; current-resource replay admission is retired.

The transport boundary and recording adapters own supplementary message recording and archive reading. Recording is optional for current-state resources. Domain bodies, typed owners, per-field parser module/version attribution and collection-completeness evidence remain durable without supplementary archive access. PR/Git immutable inputs and independent thread contracts retain their required evidence. Never seal a mutable row as an immutable parser output. Preserve minimal stable code/review-target references rather than retaining normalized review edit histories.

Recorder callback and warning-output failures remain nonfatal to valid acquisition. Sanitize recorder codes through the bounded allowlist and retain only the latest 100 transport diagnostics; cancellation, transport, parser and catalog failures retain their ordinary behavior.

CAS-41 is selected: backup manifests require the verified copied database's active physical `payload_quarantine` count, strictly checked before restore diagnosis. D2 is retired/not applicable; fabricated identity remains prohibited. LFS collection preserves Git pointer bytes; attachments preserve source text/URLs. Body acquisition, automatic external URL fetching, transport archive retention/deletion, broad deletion propagation and CAS-76/CAS-77 remain deferred.

## Stable architecture and domain invariants

- Dependencies remain `cli -> application -> domain/ports`; adapters own SQLite, Git/HTTP and filesystem operations.
- Packaged production DDL is composed by `adapters/sqlite/schema.py`. Initializer, writers, readers, exchange and maintenance use the same complete DDL and fingerprint.
- Enable foreign keys and recursive triggers on every connection. Use ordinary SQLite snapshot/transaction semantics and the OS `locks/writer.lock`; never use immutable connections against a mutable catalog.
- Service, repository and Source registration UUIDv4 are portable identities; local Source IDs are separate. URLs/names never merge identities; explicit equivalence assertions do not rewrite facts or coverage.
- Persist signed int64 Unix epoch microseconds with `_us` suffixes. NULL represents unknown; zero and negative values are valid.
- Preserve coverage v2: exactly five claim columns and explicit ownership. The complete set at the latest observation time determines the current state, including unknown/conflict; no fallback to older complete claims, fabricated remote observations or unjustified completion.
- Documents use `(change_request_id, kind, provider_change_request_document_id)`. Exact UTF-8 body SHA-256 identifies text. Do not introduce a document surrogate/version table or mutable parser metadata into shared document identity.
- Preserve necessary domain text, verified raw Git object bytes, typed parents/owners and truthful field evidence. Parser versions, receipt order, UUID ordering and parsing timestamps cannot resolve incomparable domain updates. Missing fields must not acquire another observation's evidence; real contradictions remain visible.
- Backup verifies source and copied domain bytes and the active physical quarantine count (CAS-41); restore validates before diagnosis and uses a fresh retained stage and atomic no-overwrite publication. Do not silently discard known quarantined content or its diagnostics.
- Job plans freeze Source registrations and nonsecret settings at creation. Resume resolves credential references at execution. CAS-76/CAS-77 and broader lifecycle decisions remain deferred.

## Transitional schema 19 mechanisms (preserve only until replaced)

These constraints protect **currently reachable historical PR, thread, Source inventory and Git paths**. They are **not** instructions to perpetuate the old parser architecture or saved HTTP inputs in new schema designs. When an owner-approved ADR replaces a mechanism, remove its obsolete tables, CLI, FKs, views, triggers and tests coherently; preserve the underlying domain correctness guarantees without compatibility shims.

- Retained historical interpretations currently use distinct acquisition/retrieval and `parsed_result_uuidv4` identities, one repository or Source owner, typed input/output membership and sealed immutable publications. Current Issue/review values are **not** immutable parsed-result members and require only the current module/version and field-evidence contract.
- Historical `parser_profiles`, capability definitions, whole-definition verification, invalidation, receiver-local trust, profile/fact-selection predecessor DAGs and eligibility rules exist only for legacy historical consumers. Their replacement must not require multiple re-interpretations, selected profiles or whole-parser verification/trust as ordinary domain prerequisites. Do not let removal manufacture a current winner or admit incomplete output.
- Existing `stored_bytes` and `payloads(representation,sha256)` share physical integrity checks between required Git/domain content and **still-retained historical HTTP proof inputs**. Only raw Git content can enter rejected-byte staging; explicit repair requires verified actual Git format/OID/type/size and a mapped Git object. Quarantine, complete byte scans and CAS-41 remain valid for retained physical bytes. Do not interpret this shared storage as permission to retain new API-original functionality.
- Current one-repository exchange carries typed owners and required domain bytes. Original-only export/import/promotion was retired; still-supported historical collection/304 proof and publication may require original inputs. `--fetch`/`--collection` selection is retained for legitimate domain/proof closures. Exclude Source-wide inventory, receiver-local trust/quarantine and operational validator caches. Stage unknown dependencies and actual conflicts without inventing an acceptance order.
- Preserve the existing incremental/restart and conditional HTTP behaviors where reachable, but these are **deferred redesign boundaries**, not a mandate to keep original response bodies, exact legacy manifests or old operational schema in a future replacement. Do not weaken truthful timestamps, provenance or collection completeness to remove them.

## Verification and evidence

Use one practical Python/SQLite environment and report actual versions. For runtime/schema changes, run focused tests during integration, then the complete applicable ordinary suite, fresh DDL/FK/integrity and JSON checks, lint/format and isolated wheel/sdist installs. Documentation-only changes may use appropriately scoped prose/diff checks, and must not claim runtime acceptance from those checks. Test counts are evidence, not targets. Retired migration-only cases are documented separately from current-contract replacements. Preserve meaningful behavioral tests and disclose failures, skips and unexecuted checks separately.

While the **retained historical parser-verification mechanism** is still active, its built-in artifact binds implementation hashes to actual capability-test evidence; regenerate only from successful relevant tests and a frozen definition. Final acceptance must run without test bootstrap overrides. Retire this certificate requirement when that historical mechanism is coherently removed under the accepted parser-provenance ADR. Hosted acceptance must correspond to the exact submitted feature HEAD/effective tested tree.

# RefObservation future acceptance scenarios

Fixed baseline `ab0786cfa29e7be129c7b17517a469ec1cf8b215`; these are specifications for later implementation/review, **not executed tests**. `K=(origin_uuidv4,ref_observation_uuidv7)`; R/S are distinct typed full roots; F is one exact byte-valued ref; source scope includes actual visibility. D1–D6 refer to companion ADR. All synthetic data only.

| ID | Given / action | Required observable outcome |
| --- | --- | --- |
| A01 | Independently read identical repository/F/R twice | Two valid v7 keys K1/K2, distinct immutable observations; equal structural Mapping content may be shared; no dedup of observation (D1/D4). |
| A02 | Replay exactly K1 and its report via X→Y→Z→X | Full semantic replay is idempotent; original subject, coordinates, issuer, event and provenance survive; no extra occurrence or receiver-local identity (D1/D2/D6). |
| A03 | Original K has present but unknown target; later genuine original supplemental report C2 says R | Same K; both immutable claims and distinct actual original evidence retained; unknown is not overwritten; C2 may support separate R-specific proof (D2/D5). |
| A04 | An existing evidence coordinate C1→R is replayed as C1→S or another subject | Reject incompatible replay atomically; K, C1, group, role proof and body remain unchanged (D1/D2). |
| A05 | Distinct authentic-as-reported coordinates C1→R and C2→S under K | Owner-selected B: retain both immutable Claims and expose conflict, without selecting a winner or rebinding evidence. Exact duplicate replay is idempotent; existing coordinates cannot change value. Comparable present/confirmed-absent contradictions under the same K and immutable subject also remain as conflict (D2). |
| A06 | Existing K reused with different repository/F/source/immutable scope, or malformed/incorrect UUID version | Refuse identity misuse and preserve existing state; v4 origin/v7 observation and variant are validated; same K alone is no proof (D1/D2). |
| A07 | K1 and K2 have same typed R, semantic interpretation/version/scope; decoder evidence D1 and D2 independently establish same mapping | Content may share; K1/K2 and their original report links plus D1/D2 evidence remain distinct. Exact D1 retransmission is idempotent. Different interpretation/scope is not silently shared (D4). |
| A08 | K has R-specific role proof; supplemental or conflicting report names S | Existing proof and body remain bound to exact C→R; no S body authorization from R evidence even if mapping values coincide (D2/D5). |
| A09 | For explicitly named F, a successful lookup or completed enumeration establishes absence within actual source/visibility | Persist scoped absence, concrete completion evidence and links; prior presence stays; no claim about invisible or other sources (D3). |
| A10 | F is missing from partial/failed enumeration, unobserved, or a target resolution fails | No confirmed absence; report failure/unknown via appropriate Operational path, do not create negative rows for unbounded namespace (D2/D3). |
| A11 | One discovery performs two local scans, which agree | Preserve each actual scan identity/scope/evidence and links to its own members; do not claim atomicity or remote absence. A standalone single-ref observation works without enumeration (D3). |
| A12 | Same pinned result is redelivered after crash, versus read again after original result lost | Exact preserved original result reuses K; genuinely new read gets fresh K. Original lost means no rebind. Finite cumulative work remains charged to same acquisition request where applicable (D1/D6). |
| A13 | Crash after read but before pin; after pin before Core; after admission before ack; lose Operational; concurrent deliveries | No fabricated replay identity; pinned exact result can retry, admitted facts survive Operational loss, concurrent exact retries are idempotent, conflicts never overwrite, actual work accounted (D1/D2/D6). |
| A14 | Ref bytes include non-UTF-8 and are exchanged/backed up | Exact bytes roundtrip and equality is byte-accurate; no Unicode replacement or guessed normalization (D1). |
| A15 | Adapter produces direct target but no symbolic/resolved/peeled data; separately it genuinely reads a symbolic target and a peeled target | Preserve each meaning distinctly; unknown fields remain unknown, typed full OIDs roundtrip, no fabricated data (D2). |
| A16 | Direct tree root yields a sufficient local single-path proof for one note | Permit that note body only after exact structural and body checks; no invented commit, no whole inventory requirement, proof covers only checked path (D5). |
| A17 | Sender says verified, or body hash/type/OID is correct, but receiver lacks relevant root-to-note path | Retain permitted attributed metadata only; do not durably retain unproven body, staging/pending payload is not a hidden file archive (D5/D6). |
| A18 | A real role proof relates a note to an ordinary file blob | Note body may be admitted when all checks pass; no permission propagates to the annotated file's bytes (D5). |
| A19 | Export/import explicitly selected rootless unknown-target or scoped-absence observation | Roundtrip K, scope, report, and needed enumeration link without fake OID, payload, Context or source registration; repeated/onward transfer remains idempotent (D6). |
| A20 | Select only object root R when rootless K exists; select K explicitly in a separate request | Object selector includes only actual root links; it does not fabricate membership for K. Explicit ref selection can include K and its dependencies (D6). |
| A21 | Two different immutable partial groups cover disjoint members | Neither is mutated, and no union is declared complete; any separately admitted complete group requires its own sufficient proof. Atomic visibility on failures (D4). |
| A22 | Two attributable Notes member reports disagree at same slot, versus one report coordinate is rebound | Preserve true Notes alternatives with derived conflict per ADR 0020; reject coordinate rebinding. Presence conflicts follow the separately selected ref-result rule in A29 (D2/D4). |
| A23 | Query auto vs explicit core_only; Exchange include_context=False with coexisting bad Context; Core-only receive missing Operational | Preserve current defined opening/validation behavior and typed failure, not silently bypass checks because Context data were excluded (D6). |
| A24 | Latest Coverage candidates are stale, equal-time conflicting or unknown while older complete exists | Follow existing latest-candidate/stale/conflict contract; no fallback to older complete, no UUID order substituted for time (D6). |
| A25 | Corrupt authoritative retained bytes detected during ordinary operation | Catalog-wide stop, suspect source read-only; verified fresh restore and validated salvage merge; no ordinary same-DB failover (D6). |
| A26 | Git-only metadata backup vs paired backup and onward restore | Correctly label scope, preserve new observations/claims/evidence and exact retained body where eligible, independently validate pairing/format/checksums; Access scope remains separate (D6). |
| A27 | Reuse K with changed immutable subject visibility; separately submit genuine additional evidence with the same subject; observe a different scope | Reject the changed K subject; append genuinely distinct evidence without rebinding; issue a separate K for an actual observation with a different scope. Evidence with incomparable scopes is not forced into a conflict or winner (D1/D2/D4). |
| A28 | Work budget expires during enumeration/proof, or retry rereads same source | Preserve admitted immutable units only; no truncation/false completion/hidden payload; charge actual performed work cumulatively, explicit finite limit increase needed for continuation (D6). |
| A29 | Separately attributable comparable present and confirmed-absent reports under the same K and immutable subject | Retain both immutable claims and expose conflict; never silently choose a winner or rebind evidence; exact replay remains idempotent (D2/D3). |
| A30 | Acquisition fails, subject scope differs, or a later actual ref read occurs | A failure does not assert absence; reject changed subject under K and issue a new K for an actual new observation (D1–D3). |

## Proposed interfaces (not fixed SQL schema)

- `RefObservationKey(origin_v4, observation_v7)` validates exact values; `RefObservation(subject, key)` has immutable self-contained repository/ref/source/scope. `RefObservationClaim(key, original_report_coordinates, result)` stores actual presence/form/typed targets. A direct semantic claim reference includes all coordinates needed to distinguish reports and prevent root reuse; no digest-only identifier. Full equality checks subject, evidence coordinates and value. Reject a changed immutable visibility subject under K; append genuine additional evidence only when the subject is unchanged, and give an actual different-scope observation a new K. Owner-selected B retains separately attributable incompatible known target claims and exposes conflict; no silent winner. Same-coordinate rebinding is rejected and exact replay is idempotent. Comparable present and confirmed-absent claims under the same K and immutable subject are also retained with explicit conflict; acquisition failure is not confirmed absence.
- `RefEnumerationObservation(event_identity, source, scope, status, completion_evidence)` identifies one actual scan; explicit link carries event, observation key, claim and whether item/absence derivation. Event ID must designate a real enumeration; its format and issuer protocol are I2 proposal to review against no-surrogate policy. Multiple discovery scans never become one fictitious event.
- `NotesMapping(typed_root, interpretation_kind/version/scope, mapping coordinates)` is reusable content; `NotesMappingClaim` and `NotesMappingGroup` reference original result, real attribution and full immutable asserted content/scope. `NotesMappingEvidence` names decoder/version and checked scope, distinguishes original claim from receiver-local analysis. `NotesRoleEvidence` binds exact claim + typed root + actual target/note/path/proof. An admission service consumes role proof plus body and verifies both locally before immutable insert.
- Selective Exchange supports selection by real observation key or documented ref/repository selector independently of selected OIDs. Dependency resolution includes exact subject/claim/evidence; object-only selection has no magic rootless matches. Unknown/absent metadata can roundtrip without payload, Context or invented object; receiver rechecks relevant proof.
- Physical tables/constraints, encoding, indexing and transactions remain engineering: propose lossless `ref_name_bytes` BLOB, semantic-composite uniqueness and a single atomic transaction for each whole group; reject incompatible coordinates before any visible partial result. This does not prescribe eight physical tables. Choose supported UUIDv7 source and validate variant/version. Generate packaged DDL fingerprints from actual format, with no new runtime switch implied.

## Owner decision and remaining boundary

The owner selected **B** for K with two genuinely separately attributable known target claims R and S: retain both immutable Claims and expose conflict; do not select a winner or rebind evidence. Exact duplicates are idempotent and a reused evidence coordinate cannot change value. This affects I1 admission, I2 writer behavior and I3 exchange/query. The owner also selected the same preservation and explicit conflict for comparable present and confirmed-absent claims under the same K and immutable subject. Failure does not establish absence; changed subjects are rejected and new observations receive new K.

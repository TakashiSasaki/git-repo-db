## F01 — finite kind/parent semantics

- **Condition:** Construct repository-parented `document`, Issue-parented `thread`, commit-target review (without fabricated PR), or `discussion`/`event`/`commit`/`analysis_result` as an unrecognized kind. PR03 and PR05 test real production admission; PR04 is a valid PR-document control. GitLab Issue/commit Discussions motivate a real-spec example; arbitrary event and movable standalone-document examples are explicitly hypothetical.
- **Actual:** ResourceKey accepts nonempty kind strings but packaged DDL rejects unsupported kinds/parents. PR09 demonstrates that changing the parent of a document changes its key under the current contract. Reinterpreting another kind as “discussion” does not establish faithful semantics.
- **Expected broader meaning:** Store the genuine information identity, actual parent/target, and query it as that kind without inventing a PR, dropping identity scope, or repurposing an approved Repository role.
- **Source:** [ResourceKey L639](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/domain/p1_context.py#L639), [DDL L25](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/p1_ddl/context.sql#L25), [admission L75](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/p1_context.py#L75). ADR 0017 natural keys, ADR 0029 carried-forward document identity, ADR 0030 Q-S6/Q-S10 and six-role limit.
- **Impact:** New Provider adapters, kind-specific reads, parent identity, Collection member validation, graph selection/Exchange, schema fingerprint and semantic backup validation. Current supported PR/Issue semantics remain valid.
- **Response:** Existing `annotation`/`assessment` only when that is the actual meaning; otherwise compare extending kind/parent validation with independently identified content plus explicit relations. Do not choose based only on fewer schema edits.
- **Accepted design change needed?** Yes if changing settled document identity/parent rules or approved relation roles; the exact extension needs designer review. An additional genuine kind may be additive but still needs a reviewed contract. No change in this PR.

## F02 — namespace normalization is an adapter obligation

- **Condition:** Two GitLab projects both have `iid=7`; a caller supplies bare `"7"` as service-wide issue ID. Gerrit's bare Change-Id provides another real-spec collision risk. PR02 uses specification-derived synthetic input, not a live fetch.
- **Actual:** Bare keys are identical and deduplicate; a reversible genuine project/ID coordinate keeps them distinct. PR01 proves different services remain separate; PR10 tests existing GitHub REST/node namespacing. Production raw intake imports GitHub normalizers, not GitLab/Gerrit/Gitea implementations.
- **Expected meaning:** Identity must include its actual namespace. Rename/transfer/reuse must not mint a new observation or merge different resources accidentally. Provider specification/version, API ID variant and native scope must be explicit.
- **Source:** [ResourceKey L639](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/domain/p1_context.py#L639), [GitHub IDs L50](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/github/production_intake.py#L50), [acquisition imports L21](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/application/acquisition.py#L21), [Provider registration L374](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/production_context.py#L374). ADR 0017 and ADR 0030 original-ID constraints. [Official source receipts](evidence/context-provider-agnostic/research/provider-sources.json).
- **Impact:** Every new adapter and replay/Exchange consumer. Current key can carry a composite text identity; arbitrary caller concatenation is not a common contract. Provider-global identity reuse guarantees are unverified; no actual reuse defect is claimed.
- **Response:** Prefer real globally scoped IDs; define an injective tagged composite encoding where the native identity is composite, with API-version/lifecycle tests. Preserve opaque IDs. Add Provider adapters using typed normalized units, not a relabeled GitHub payload.
- **Accepted design change needed?** Usually no for represented semantics; genuine identity reuse/movement without sufficient upstream coordinates may require a new decision. Do not fabricate a surrogate or derive identity from URL/name/OID.

## F03 — target and actor semantics beyond generic storage

- **Condition:** An analysis targets a commit-relative file range, reports an author distinct from publisher/source, or is authored locally and relates to several repositories.
- **Actual:** PR06/07 and CE roundtrip prove annotation text, explicit Provider-resource relations, assessment fields and unacquired typed OID reports can be retained/read. They do not define typed path encoding, line/range/side, author/publisher roles or a local operation's genuine identity. No file-position roundtrip is claimed.
- **Expected meaning:** Information identity and target identity stay separate; Git object format/OID is not object type, repository membership or body presence. Local issuer, author and source claims must not be conflated or authenticated by a string.
- **Source:** [field candidate L701](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/domain/p1_context.py#L701), [relation/member checks L520](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/production_context.py#L520), [reported vs required Core reference L995](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/production_context.py#L995), [query projection L1042](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/application/production_query.py#L1042). ADR 0005/0008/0014/0017/0028/0029/0030.
- **Impact:** Future normalization, validation, typed query and search filtering, and Exchange semantic roundtrip. Storing arbitrary JSON does not supply those contracts.
- **Response:** First define typed value/role conventions over existing fields and relations. Confirm genuine source/operation identity for local reports. Consider a dedicated relation/entity only when the concrete identity/constraint cannot be expressed faithfully.
- **Accepted design change needed?** Not necessarily for typed conventions; new Core-Repository roles or changed responsibility do. No full edit history or binary archive is requested.

## F04 — Coverage clock and visibility partition contract

- **Condition:** A generic adapter combines incomparable Provider clocks or different permission/filter views in one resource/repository Coverage owner. CE characterization submits partial at numeric 900 followed by unknown at numeric 100 under the same owner; the hypothetical labels are not carried in the five columns.
- **Actual:** 100 is stale because latest-observation comparison is numeric within owner. There is no independent clock-domain dimension in CoverageClaim. Distinct genuine collection provenance/scope keeps evidence separate; changing scope under an existing immutable collection key is rejected. Current field-clock handling does not extend to Coverage by implication.
- **Expected meaning:** Completeness applies only to the observed namespace, visibility, filter and comparable acquisition-clock domain; never claim global completeness from permission-limited enumeration.
- **Source:** [CoverageClaim L27](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/domain/p1_coverage.py#L27), [CoverageScope L2371](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/domain/p1_context.py#L2371), [admission/projection L1013](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/p1_context.py#L1013), [Collection L594](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/production_context.py#L594). ADR 0028 times; ADR 0029 Coverage carry-forward; ADR 0030 unchanged five columns.
- **Impact:** New Provider collectors and summary APIs. The characterization complies with the existing numeric policy; it is not an implementation violation. Applying incompatible times to that policy would be an adapter error.
- **Response:** Specify acquisition time comparability and permission/filter ownership. Partition genuinely independent collection observations using their actual provenance and explicit scope; present incomparable scopes independently. Do not manufacture provenance/timestamps or equate Provider update time with acquisition time.
- **Accepted design change needed?** No for safe explicit scope usage. Whether cross-domain summaries are required, and how they preserve uncertainty, remains a designer question. Keep the physical five-column claim model.

## F05 — structured metadata Search extension

- **Condition:** Assessment field contains an object such as `{"scanner":"audit","score":2}`; user expects a search hit from a nested scalar.
- **Actual:** Generic typed reread and Exchange preserve the object (CE roundtrip). Source inspection shows Context search extraction selects string values/text bodies, not arbitrary recursive JSON. This exact nested-scalar search negative is source-reviewed, not an additional executed probe. Existing I4 search tests cover current text projection and fallback.
- **Expected broader meaning:** If structured analysis search is selected as a feature, its indexed fields, value types and predicates need explicit semantics; preservation alone does not promise full-text discovery of every value.
- **Source:** [Context extraction L509](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/adapters/sqlite/production_search.py#L509), [typed query L1042](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/application/production_query.py#L1042), [fallback L1461](https://github.com/TakashiSasaki/git-repo-db/blob/efb55af84ccbf1183d47547d22bb6c57d8fbc8f9/src/repo_catalog/application/production_query.py#L1461). ADR 0029 Search derivative boundary and preserved PF-P15/16.
- **Impact / response:** Optional typed query/filter or rebuildable search projection extension. Keep Context authoritative; add paired scan/fallback equivalence tests, generation fencing and projection-specific tests if implemented. No Mapping or Core change follows.
- **Accepted design change needed?** Usually no for a derivative projection that respects existing authority; a new persistent meaning or broader retention rule would require review. Context schema/identity/Coverage/backup can stay unchanged.

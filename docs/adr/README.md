# Architecture Decision Records (ADRs)

Read the current scope before implementation. This index describes accepted target decisions, not implemented or verified behavior.

**Accepted ADR governance: [ADR 0011](0011-adr-governance.md) and [the operating policy](policy.md).** Full/Mini-ADR [templates](template.md) and [Mini template](template-mini.md) are repository files; the optional [adr-workflow skill](../../.agents/skills/adr-workflow/SKILL.md) is procedural. The policy's section 9 documents the bounded pre-adoption exception for existing ADRs 0001–0027: keep still-binding clauses until a separate semantics-preserving review authorizes retirement. ADR numbering allocation watermark: **0028** (0011 is now accepted, not a free gap). Acceptance, merging, implementation and executed verification remain distinct.

**Latest accepted origin policy: [ADR 0027 / Option A](0027-unauthenticated-external-capture-origin-reports.md).** External Capture issuer/source claims may be retained as unauthenticated attributed reports; no application PKI or electronic signatures at present. Preserve original Capture/semantic keys, actual provenance qualifications and immutable binding; neither UUIDs nor reported identity authenticate the issuer. Local byte/notes-role checks retain their exact scope, including for salvage. **Remaining owner blockers: provisionally 0 for the current migration scope**; engineering work and deferred features are not complete or newly authorized. Future genuine blocker questions include the remaining-count estimate and explain any increase.

**Latest accepted corruption recovery: [ADR 0026 / GCTX-M10](0026-stop-salvage-restore-merge-after-corruption.md).** Immediately enter catalog recovery mode after authoritative corruption, preserve the source read-only, serialize salvage candidates, restore a revalidated backup into a fresh destination and merge only admissible revalidated data. No quarantine state/count/release/retirement belongs to the new target; old CAS-41 count/order remains historical evidence only, with actual database/manifest/domain/pairing validation retained. Normal backup/restore cannot accept known damaged bodies. Preserve forensic evidence and honest incomplete recovery scope; no same-DB I2 continuation or imported verification authority. This supersedes the former M10 A/B/C question, preserves strict Core and paired-backup/domain rules, and authorizes no implementation or actual recovery.

**Latest accepted request scope and blocker correction: [ADR 0025 / B02-R04 A](0025-cumulative-request-budgets-and-scoped-blockers.md).** One explicit acquisition request accumulates actual work across continuation/resume/retry. Defaults, counter units and progress/resume mechanics are agent-owned engineering work under accepted policy, not owner blockers. GCTX-M10 recovery is subsequently fixed by ADR 0026; its detailed mechanisms remain engineering work. No implementation or merge permission.

**Latest accepted accounting basis: [ADR 0024 / B02-R03 A](0024-actual-notes-resource-work-accounting.md).** Charge actual byte/verification/metadata/proof processing; safe reuse avoids fictitious full-body charges, but reprocessing and actual reference/proof work still count even when insertion deduplicates or rolls back. B02-R04 cumulative request scope is fixed by ADR 0025; remaining counter/default/resume choices are engineering work; no runtime or merge permission.

**Latest accepted notes resource policy: [ADR 0023 / B02-R02 A](0023-configurable-finite-notes-resource-budgets.md).** Require finite configurable raw-note/aggregate-work/proof-traversal limits, honest limit stops, preserved admissible metadata/atomic units and explicit retry after a finite configuration increase. No truncation, hidden pending bodies, false closure or deletion of admitted bytes. B02-R03 actual-work accounting is fixed by ADR 0024; B02-R04 request scope follows ADR 0025; counter/default/resume choices are engineering work. Exact notes grammar and B03 remain separately scoped work; GCTX-M10 recovery is fixed by ADR 0026.

**Latest accepted note-body admission threshold: [ADR 0022 / B02-R01 A](0022-receiver-verified-notes-role-admission.md).** Require receiver-verified relevant notes structure and exact body checks before durable retention. Source reports remain useful metadata but cannot authorize a durable unproven body. Direct-tree roots and partial sufficient mapping proofs remain valid; no whole-inventory or target-body requirement. B02-R02 configurable finite budget policy is fixed by ADR 0023; B02-R03 actual-work accounting is fixed by ADR 0024; B02-R04 cumulative request scope is fixed by ADR 0025; remaining budget details are engineering work; exact supported proof grammar and B03 remain unfinished; GCTX-M10 recovery is fixed by ADR 0026.

**Latest accepted notes claim/group keys: [ADR 0021 / B01-R06 A](0021-direct-semantic-notes-claim-group-keys.md).** Direct semantic composite PK/FK uses the actual Capture UUIDv4 pair, typed slot, asserted value and genuine provenance. Whole immutable group value/scope participates in group identity; no surrogate or digest replaces it. B02-R01 role-evidence strength is fixed by ADR 0022; B02-R02 finite configurable budget policy is fixed by ADR 0023; B02-R03 actual-work accounting is fixed by ADR 0024; B02-R04 cumulative request scope is fixed by ADR 0025; remaining budget details are engineering work, not owner blockers; B03 remains unfinished; GCTX-M10 recovery is fixed by ADR 0026.

**Latest repository-wide key policy: [ADR 0017 / KEY-P01](0017-domain-keys-without-storage-surrogates.md).** Prefer actual natural/domain composite PKs and prohibit storage-only surrogate row IDs across Core, Context, Operational and Search-facing authority. Permanent repository UUID and real capture/physical instance distinctions still apply; [ADR 0018 / B01-R03](0018-notes-capture-uuidv4-composite-identity.md) fixes direct two-UUIDv4 capture keys while compatible partial/replay fact admission is fixed by [ADR 0019 / B01-R04](0019-monotonic-notes-capture-fact-admission.md); B01-R05 competing member report preservation fixed by ADR 0020; B01-R06 direct semantic keys fixed by ADR 0021.

**Latest product scope: [ADR 0014 / GCTX-S01](0014-history-and-notes-catalog-without-file-archive.md).** The product does not archive ordinary repository-file blob bodies. It retains Git metadata, commit/tree/tag representations when acquired, and purpose-bound Git notes content. Notes are blobs at the Git object layer, so a blanket blob ban is incorrect. [ADR 0015 / B01-R01](0015-automatic-git-notes-ref-discovery.md) fixes automatic notes namespace discovery plus explicit additional ref names, **not** note-body admission or complete enumeration. Earlier raw-body admission/repair decisions apply only to retained metadata/notes and legacy obligations. B01-R02 observation identity is fixed by [ADR 0016](0016-immutable-notes-ref-capture-observations.md); B01-R03 UUIDv4 capture identity is fixed by [ADR 0018](0018-notes-capture-uuidv4-composite-identity.md); B01-R04 compatible incremental facts/replay are fixed by [ADR 0019](0019-monotonic-notes-capture-fact-admission.md); B01-R05 competing member reports are now fixed by [ADR 0020](0020-immutable-competing-notes-member-claims.md); B01-R06 semantic claim/group identity is fixed by ADR 0021; B02-R01 role-evidence strength is fixed by ADR 0022; B02-R02 finite configurable budget policy is fixed by ADR 0023; exact proof grammar and B03 completeness remain unfinished; GCTX-M10 recovery is fixed by ADR 0026.

**Latest accepted shared contract: [ADR 0028](0028-classified-times-and-sha256-exchange.md).** Owner-selected positive-or-NULL observation/Provider times, required positive Coverage coordinates, signed native Git times, and SHA-256-only Exchange integrity. No HMAC/authentication claim; no public Schema 21 activation. Decision accepted; implementation and verification require separate evidence.

**Allocation/adoption:** ADR 0011 was explicitly adopted through [governance PR #52](https://github.com/TakashiSasaki/git-repo-db/pull/52) on 2026-10-15, after the accepted design stack was merged by PR #69. It does not renumber ADRs 0012–0027, retire still-binding historical decisions or authorize bulk migration. **Highest allocated ADR ID: 0028**. Future allocations must inspect this watermark, Git history and live remote branches before assigning a new four-digit ID.

The [transition plan](../architecture/git-core-context-transition-plan.md) describes the redesigned implementation sequence. Old Phase 2 handoffs and accepted records remain evidence of their original decisions, subject to the explicit scoped override in ADR 0014. Neither old wording nor a passing documentation check is authority to implement an excluded file-storage path.

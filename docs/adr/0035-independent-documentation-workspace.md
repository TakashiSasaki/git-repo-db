# ADR 0035: Independent documentation workspace

- **Decision & Context:** Human-facing derived documentation belongs in an isolated `documentation/` project with its own lock, environment and outputs, outside the root uv workspace. Documentation follows a selected product source SHA/tree and input hashes; product work never waits for documentation to catch up. Extract neutral schema introspection before moving renderers. Preserve current IR/output semantics, implemented three-store coverage, composite foreign keys, generated columns, partial uniqueness and DDL fingerprints. Canonical ADRs, contracts, machine inputs and historical evidence remain in place; generated copies are read-only staging, never competing editable authority.
- **Constraints / Do NOT:** No product semantics, Transfer fences, SQLite policy, minimal distribution boundary or source/config/build-context cache validation changes. No blanket `docs/**`, root-input or unknown-path exclusions. Preserve every existing test obligation through an exact one-to-many node map. Product verification excludes rendering dependencies; full release evidence must separately account for both product and documentation obligations and may not claim complete acceptance when either required scope is unverified. Reuse Pages and its publication allowlist; this proposal authorizes no publication, required-check changes or main merge.
- **Reason & Ref:** Current product setup installs the docs group and Access builds MkDocs. The product boundary audit imports introspection from the renderer module (which itself does not import MkDocs). Separate these concrete dependencies without weakening safety gates. See the [bounded plan](../implementation/documentation-separation-plan.md) and [file/node ledger](../implementation/documentation-separation-ledger.json). Level 2: workflow/dependency-boundary refinement, no accepted product decision reopened. The owner approved SEP0–SEP4 design, implementation and independent verification on 2026-10-26, explicitly excluding main merge, publication and required-check settings. That permission is not adoption of this ADR. The owner explicitly adopted this workflow and release-accounting contract on 2026-10-26 at13:53:18 UTC; see [adoption provenance](../implementation/adr0035-adoption-20261026.md).

## Neutral IR and release contract

The neutral producer retains complete SQL and available SQL/DDL fingerprints for tables, views, triggers and indexes (including null SQL for SQLite-created indexes), ordered composite FK column pairs, generated VIRTUAL/STORED classification, partial-unique predicates versus unconditional constraints, and current implemented Core/Operational/Search coverage. Keep structural verification independent of rendering. HTML's deep-copied/truncated trigger representation is presentation only and must never feed product inventory or provenance.

Ordinary product checks and merges do not depend on documentation rendering. Complete release acceptance remains the conjunction of independent local and hosted product **and** documentation obligations, with exact replacement of every moved/split test node and matching selected product source/IR provenance. Product-only results are valid scoped results when documentation is absent or broken, but `full_acceptance` must remain false. Keep documentation source SHA/tree distinct from its selected product source SHA/tree and the complete neutral IR digest; record input/artifact hashes and actual independent execution contexts. A documentation source commit need not equal the selected product commit, but incompatible or missing provenance fails complete release acceptance. Adopted policy; executed evidence and complete release qualification remain separate.

# Current-resource column liveness and adjacent cleanup

Review baseline: PR #13, `db3a5ecfbf95b4c1318198aa308ca6dc749876a1`,
schema 14 checkpoint; active follow-up format: schema 15. This review follows the packaged `schema_sql()` composition and the
production writers, ordinary readers, exchange, JSON guards and maintenance.
Historical schema-hardening SQL is not the runtime schema. All measurements use
disposable synthetic data; no retained user catalog or live Source is involved.

## Column disposition

`I` means `issue_resources`; `R` means `review_resources`. Grouped rows list
every baseline column in these two tables. `CurrentResources` is the transactional
writer after provider projection; provider producers below are in
`adapters/github/current_parser.py`. `issue_queries`, `pr_queries`,
`target_queries` and `index` are meaningful readers. A `SELECT *`, generic JSON
serialization or an equality/hash loop alone does not establish a product use.

For all retained columns, full/selective exchange reconstructs a typed current
candidate and closes required current-owner/profile/body dependencies. Original
capture identifiers may be a detached provenance snapshot after transfer;
exchange does not expand into an unrelated repository or its Source registration.
Backup copies the verified physical
catalog, rather than choosing columns; restore validates the copied database.
Neither operation requires the supplementary transport archive. These common
properties are shown as `candidate / copy` below. Generated columns are excluded
from the portable candidate and regenerated by SQLite.

## Adjacent paths

The former `reviews` and `review_comments` marker tables, their write paths and
`document_observations.review_thread_provider_resource_id` are already absent in
the baseline. The `documents` and `document_observations` production tables
exclude review kinds, and `ApiFacts.document()` rejects them. This follow-up must
not count that previous removal as newly completed work.

`pr_queries._document_rows()` returns retained PR document rows with an explicit
`NULL review_thread_provider_resource_id`. Its review generator returns only
`resource_lifecycle='current'` rows, including when `document_observations=all`.
Therefore the downstream historical lookup of a thread from the same
`parsed_result_uuidv4` cannot run. That lookup and its unused selection variables
are removed; current review documents still attach the selected independent
thread interpretation. Actual `review_thread_observations`, PR document/title/body
history, Git/code facts, parsed results and their required inputs remain live.

`exchange.LOCAL_COLUMNS` previously named three columns absent from the complete
production DDL: `repositories.current_snapshot_id`,
`change_requests.current_change_request_observation_id`, and
`documents.current_document_observation_id`. Those three exclusions are removed.
`repositories.preferred_repository_endpoint_id` remains: repository identity writes
and endpoint selection reads it, maintenance checks it, and its deferred
composite FK prevents cross-repository endpoint preference. Exchange deliberately
keeps that operational choice receiver-local. The similarly named
`current_snapshot_id` query result and `current_change_request_observation_id`
collector SQL aliases are meaningful derived values, not obsolete storage.

Transfer changes the child's validated current repository/binding/number only.
The captured endpoint, Source, repository/binding, observation/parse times and
field evidence remain untouched. Export of current repository B includes its
transferred comment with captured A context, but does not pull A or Source A into
the single-repository unit. A receiver without those registrations preserves
the same detached snapshot on import/reexport. Snapshot identifiers retain
canonical types and service consistency; matching registrations, when present,
must agree with the captured repository/Source relationship.

## Baseline physical retention measurement

Python 3.12.14 / SQLite 3.53.1. A temporary directory held the complete production
DDL and the synthetic `test_current_resources.resources` fixture. Twenty ordered
imports edited one Issue with distinct 1,020-byte UTF-8 bodies. No collection
receipts, archive messages or immutable document observations were created.

| Observed quantity | Value |
|---|---:|
| Current Issue rows | 1 |
| Immutable document observation rows | 0 |
| Interned bodies / exact body bytes | 20 / 20,400 |
| Bodies no longer referenced by current resources or retained documents | 19 / 19,380 bytes |
| SQLite pages / page size | 870 / 4,096 bytes |
| Body rows after 20 identical imports and 20 authoritative identical live checks | 20 |
| Identical import SQLite `total_changes` delta | 20 (only publication revision updates) |
| Identical live SQLite `total_changes` delta | 40 (20 current-row and 20 publication revision updates) |
| FK / integrity checks | No FK violations / `ok` |

The reference query checked all three production text-body FK owners:
`issue_resources`, `review_resources` and `document_observations`. The physical
catalog contains its fixed schema and operational state, so page count is not a
body-storage estimate. These numbers establish current-only unreferenced text
retention; they do not establish that every historical body is dispensable in a
populated catalog. In particular, collection member digests and other retained
evidence need separate lifecycle analysis before any automatic deletion.

The measurement used `resources.__wrapped__(Path(temporary))` from
`tests/integration/test_current_resources.py`, with a
`TemporaryDirectory(prefix='git-repo-db-liveness-')`. Its input loop was
`version=1..20`, `body=f'fixture version {version:03d} ' + 'x' * 1000`, and
`provider_updated_at_us=observed_at_us=version`. It then repeated version 20
twenty times through `source='import'`, followed by twenty `source='live'`
admissions with observation times 21..40 and fresh `capture_context()` fences.
`Connection.total_changes` and a trace callback distinguished current-row
updates from publication revision updates. Close/remove of the temporary
directory followed the FK/integrity checks.

`intern_text_body()` compares exact existing bytes and does not duplicate a body
on an unchanged refresh. Baseline live evidence refresh called `_write()` and
updated all row columns even though semantic content was unchanged. The
follow-up writes only changed stored columns and skips an identical row, avoiding
redundant semantic assignments during evidence-only refreshes. No automatic
GC, archive deletion, retention duration or persisted-data cleanup is performed.

The new projection map was measured independently with the same twenty distinct
body edits. It kept exactly **seven current evidence entries** from the first
edit through the twentieth (`body`, `title`, `state`, the metadata object,
`labels`, `nested`, and `nested.known`), with one resource row and zero immutable
document observations. The final map occupied 3,009 UTF-8 bytes in this fixture;
FK/integrity checks were clean. Entry count depends on currently retained
mutable fields and metadata paths, rather than the number of edits. This is not
a hard constant-size bound for arbitrary provider metadata.

The baseline child-transfer trigger fired on every parent UPDATE containing
membership columns, even when membership was unchanged. It now additionally
requires an actual repository/binding/number change. Ordinary parent body edits
and identical live checks therefore avoid rewriting every child row, while a
real transfer still updates child current membership and retains capture bytes.

`last_checked_at_us` advances for accepted initial, edited and identical live
responses only when the pre-request catalog revision and captured scope match
the admission fence. The collector supplies that fence for ordinary successful
live requests. The value comes from an explicit local check time or, by default,
the response observation time, and never decreases. Import/replay preserves an
existing receiver-local check and ignores the sender's check. Provider clock,
row observation/parse attribution and per-field capture evidence retain their
separate roles; conflicting admission is not a successful current-state check.

## Focused reader verification

The changed reader is verified with current Issue/review queries, explicit
retained document/profile queries, real synthetic nested-thread collection, and
the existing E2E review-comment search with resolved/outdated thread filters:

```sh
REPO_CATALOG_TEST_BOOTSTRAP=1 uv run --no-sync pytest \
  tests/integration/test_catalog3_current_queries.py \
  tests/integration/test_catalog3_profile_queries.py \
  tests/integration/test_catalog3_review_coverage.py \
  tests/e2e/test_github_sync.py::test_pr_documents -q
```

Result after coordinated writer/DDL changes: **38 passed in 42.61 seconds**,
with no failures or skips, on Python 3.12.14 / SQLite 3.53.1.

This is a focused development check with the explicitly synthetic parser trust
fixture. Final unflagged whole-application/installed-package acceptance and exact
parser verification regeneration belong to the integration coordinator.

## Reexpressed and removed paths

The old result/input/output owner tables, profile/capability/verification/trust registries, selection DAGs, result eligibility/member views and Git acquisition publications are absent from composed Schema 20. Actual parser module/version remains in field/decoder/event evidence. The certificate artifact, generator, test bootstrap and profile administration CLI are removed. Git-only `parser reparse` remains; retrospective API replay does not.

PR/document/thread full observation series and Source full inventory observations are replaced by direct current rows and scoped evidence. Documents keep their natural key and are the sole title/body authority. The projection uses a closed modeled vocabulary, not opaque provider responses. Typed current merge shares the established sparse/null, comparable/equal/incomparable-clock, inherited origin and scoped live-fence rules. Unconditional old-value history is not a conflict-resolution mechanism.

Pending current candidates retain the same minimum typed shape, signed-int64 clocks, actual producer fields, evidenced-value presence and internal capture correlations as ordinary admission. Missing real parents can defer dependency resolution; they cannot defer validation of a candidate's own subject. Native INSERT/UPDATE guards enforce this boundary as well as Python writers and full check. Generated metadata checks use flat tree predicates, and independent pending-envelope guards avoid SQLite parser stack overflow; the same modeled vocabulary remains enforced on SQLite 3.45.1.

`fetch_occurrences`, Source input observations, raw API payload links, accepted-partial response envelopes and original-bearing exchange records are removed. Accepted partial GraphQL roots normalize child requirements, continuations and code roles while in memory. Failed/rejected responses do not become catalog bytes. Optional external recorder failures retain bounded nonfatal diagnostics. An unsolicited 304 without usable domain context triggers an actual unconditional fetch rather than inventing a previous observation.

`Store.publish`/`publication_seq` becomes `advance_local_revision`/`local_revision` across acquisition, queries, paging, maintenance, restore and CLI JSON. Nested savepoints and outer transactions roll back on body, constraint and COMMIT failure. Cleanup failure preserves the original exception with a note. A caught inner failure leaves no partial values/evidence/revision while allowing the caller's intended outer work to continue.

Graph export selects domain closure from a coherent snapshot, by repository plus optional actual collection or Git acquisition. Incoming records have a closed table/field vocabulary, portable typed key/FK resolution and byte/current-state validation. Real missing dependencies and conflicting alternatives are staged; individually valid independent records are usable before the whole delivery completes. Scope closure does not import stronger provider authenticity: a coherently omitted member cannot be detected by the sender's own digest alone.

Discarding receiver processing receipts and aliases does not duplicate natural Git acquisition roots or invalidate replay of admitted subjects. Completeness dependencies compare the actual resolved typed subjects when legitimate aliases differ; an unrelated subject cannot replace a required dependency. A missing exact captured ref remains pending, while a present contradictory target is rejected. Selected onward export follows pending ref origins through an indexed declared root dependency and forwards one genuine deferred closure candidate, without creating competing complete/incomplete versions of its physical prefix.

Git decoder validation shares pure decoding primitives with the ordinary parser. Supported settings and their key must agree; producer attribution does not authorize a fabricated text, commit field or tree name. Name checks use the owning entry's bounded canonical byte span, rather than parsing the entire tree for each entry. Queries and index rebuilds use computed valid-candidate views, while full check groups candidates by actual object to avoid repeated whole-object verification. These views are derived predicates, without stored eligibility or profile selection.

Repository-scoped Exchange does not carry a Source-wide inventory assessment. After such an import, explicit repository code queries can be complete while unqualified or Source-wide queries return the same usable hits with `inventory_incomplete`. This follows the actual scope of the received evidence and does not infer absence or a complete Source roster from one repository.

Query/search/index and explicit target diagnostics consume current API state and legitimate Git/event facts directly. API historical/profile options are retired. Git capture/history scope remains meaningful. Backup/restore consumes the same Schema 20 DDL fingerprint and physical integrity contract, independent of domain completeness.

## Boundaries and verification

No new absence deletion, physical GC, cache architecture, checkpoint retention placement, sender/provider trust, parser preference or Git interpretation policy is selected. Acquisition retains required existing semantics; genuine ambiguity remains visible. Operational credentials are never exported, and synthetic package tests use a local HTTP fixture and dummy token only.

The [test disposition](publication-free-test-disposition.json) must reconcile retired mechanism-only nodes to exact surviving behavioral nodes. Ordinary, package, schema/JSON, lint/format and selected-scale results must bind to a frozen corrected feature commit and tree. Dirty-tree exploratory runs are useful during integration but are not final acceptance. Four fresh independent reviewers must execute their own counterexamples and recheck corrected paths. A draft PR with a failed or unexecuted gate is not review-complete.

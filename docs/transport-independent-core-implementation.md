# Transport-independent core implementation boundary

The accepted [ADR](transport-independent-core-adr.md) is implemented incrementally from PR #16 (`7829a6addb05d73ab4f303eb48ba19cd9957aba7`). The current fresh format is schema 18. The [Phase 1 retirement decision](phase1-api-original-retirement.md) and [implementation inventory](phase1-api-original-retirement-implementation.md) supersede older original-preservation requirements within R1–R7. Initialize disposable fresh catalogs; no migration, merge or release is included. This boundary does not assert full ADR implementation.

## Current Issue/review resources

TP-01, TP-02 and TP-05–TP-08 apply to current ordinary Issues/comments and reviews/comments: exact domain text, typed identity/parents, field evidence, transfer capture, unresolved alternatives and established normalized collection receipts remain durable without original response bytes. Acquisition, queries/search, full/selective exchange and backup/restore work with no `fetch_occurrences`, `decoded_api` CAS or optional archive. A review requires a typed `change_requests` owner, not a retained parent PR response. Whole PR synchronization still uses the historical paths below.

TP-04 replaces `parser_profile_uuidv4` with nonempty NUL-free `parser_module` and `parser_version` on `issue_resources`, `review_resources` and `current_collection_pages`. `current_parser` stamps its own module/version, overriding caller attribution. Page attribution identifies the resource normalizer that produced the digested current members; the historical thread interpretation remains separately owned by the legacy parser. Every retained mutable field's seven-key evidence includes its actual producer, clock, observed/parsed times and capture scope. Missing fields retain their original evidence; explicit null remains an observed value. Module/version are excluded from semantic fingerprints and owner comparisons. Versions do not rank conflicting values. Current admission and views require no profile registration, capabilities, certificates, trust or selection; built-in historical profile capabilities no longer include these current families.

The current acquisition JSON guards reject transport-original, profile, parsed-result and selection references and contain no unreachable queries to their legacy stores, while preserving typed owner checks and detached Issue-transfer snapshots. Current selective exchange no longer exports profile selection closure. Issue-only queries reject obsolete profile selectors; explicit historical profile filters on PR document queries select historical documents. Current queries expose module/version and field evidence. Explicit current review-family document/search requests use typed parent and stable thread identity without historical interpretation joins. Their coverage preserves the existing repository parent-roster summary and checked collection proofs, missing bodies and unresolved conflicts; broader metadata/code/thread filters retain historical query behavior. Unknown scope kinds remain conservatively relevant. Existing incremental baseline behavior conservatively starts a full scan after a producer change; this is an operational baseline, not a new provider-ordering or completeness policy.

Changed schema objects: the three current tables, their parser module/version and current-state ownership/conflict guards, current eligibility views, current-page parser attribution guard, and generated capture/field-evidence guards. Historical capability FKs and generated capability columns remain for retained historical families. The five coverage claim columns and existing terminal/member/page proof semantics are unchanged. Existing normalized provider projections are preserved; this change does not choose a new provider-field retention policy or content GC.

## Independent infrastructure

TP-03 retires the core HTTP retrospective parsing workflow. `ParsingService` and `parser reparse` accept only retained Git acquisitions; a saved API fetch UUID is rejected before original bytes, parser profiles or historical facts are read or written. The former HTTP parser dispatch, historical replay publication and mutable-admission bypass branches are removed. `reparse-message` and its archive-backed domain parser projection are removed as part of Phase 1. Bounded `inspect-message` remains a diagnostic reader and never invokes a domain parser. Current-resource admission accepts only `live` and `import`; it has no offline `replay` mode. Git reanalysis preserves the existing acquisition, immutable bytes and explicit interpretation-selection behavior pending its separate lifecycle contract.

TP-06 separates shared CAS admission responsibilities by requiring every `intern_payload` caller to declare its representation. Git content remains `git-object-raw-v1`; remaining historical API paths explicitly declare `decoded_api`. Exact SHA-256 admission, byte comparison, atomic registration, Git OID verification, quarantine and CAS-41 backup/restore are preserved. This boundary removes the implicit transport default without pretending that remaining historical originals have already been retired. Phase 1 additionally narrows `payload_admission_staging` to rejected raw Git bytes and `unresolved_payloads` to physical-corruption diagnostics, removing its logical-payload FK columns and corresponding index/JSON guards. Explicit repair requires a real retained Git object payload reference and validates the replacement against every mapped Git object's format/OID/type/size, including a physical digest shared with an API representation. Verification scans, quarantine, backup/restore and CAS-41 continue to protect every stored physical byte; API-only repair is retired. These structural changes advance the fresh schema to 18 and do not choose a lifecycle policy.

Synthetic regressions reject HTTP reparse across retained PR, document, timeline, thread and code inputs without reading originals or changing the complete catalog. SHA-1/SHA-256 Git reparse tests preserve retained bytes and acquisition publications. Installed wheel/sdist tests exercise the retired API command and the unchanged Git reanalysis path. Existing independent adversarial assertions retain their contracts; CAS callsites merely name their existing logical representation explicitly.

## Remaining baseline and exact blockers

| Remaining objects and paths | Contract required before removal |
| --- | --- |
| `source_input_observations`, `repository_inventory_observations`; `collector.inventory_input/inventory_result`, `CollectionService.discover` | Successful, endpoint-validated live inventory still uses original input publication. Normalized inventory publication/ownership and retained provider-field inventory are undecided. The existing query exposes opaque provider metadata. Rejected inputs have no raw retry store. |
| `fetch_occurrences`, `change_request_observations`, `document_observations`, `change_request_events`, `review_thread_observations`, `code_observations`, `code_commits`, `code_file_changes`; `ApiFacts.page/result/ownership/publish`, PR/detail/document/thread/code acquisition | Domain batch/publication identity and atomic completion, historical lifecycle/resolution and retained fields. Saved fetch inputs currently protect sealed immutable output membership. |
| Historical `completion_markers`, `collection_memberships`, code listings and exchange aggregate proof | Normalized historical member/terminal proof and exchange validation. PR-list exchange rereads saved JSON to check exact member closure; dropping this would weaken correctness. |
| `validators`, PR detail 304 reuse and successful historical thread restart; legacy HTTP CAS `payloads`/`stored_bytes` | Conditional HTTP cache/restart and normalized proof contracts. The retained live paths reread accepted originals; failed-original staging, standalone offline replay and API-only explicit repair are removed independently. Domain Git objects and exact text remain required. Physical integrity and CAS-41 still cover the shared store. |
| `parser_profiles`, capabilities, verification/invalidation/local trust; `parsed_results`, inputs/publications; five profile-selection and five fact-selection tables; exchange blocked-result/selection state | Replacement historical publication and unordered fact-resolution contracts for PR/thread/inventory/Git. Existing ordinary historical readers still use these objects; removing them would choose a current winner or admit partial output. |

Successful historical publication, accepted partial GraphQL roots with error envelopes, live restart/304 reuse and domain-exchange proof are narrow Phase-2 boundaries, not permission to distribute unrelated originals. Export/import and delayed promotion require an original to be reachable from retained domain facts, Git payload ownership or exact terminal proof. Historical `--fetch` and `--collection` selectors remain for that closure; bare message/byte sets and original-only scaffolding cannot authorize an archive exchange. Existing opaque provider projections, including current resource metadata, remain a field-inventory boundary rather than a repository-wide no-original guarantee.

Fully rejected, uncommitted API collection responses retain only an attributable partial reason, truthful observed time where domain incompleteness was observed, and safe live retry context. They retain no core raw response, logical parsing-gap row or delayed raw admission. Accepted partial GraphQL roots and committed prefixes still retain exact original inputs for historical publication/live restart, including envelopes with errors; this R6 portion remains C. Error-only rate-limit responses preserve operational retry state and deadlines without creating a semantic observation. Optional external recording may capture rejected/error responses independently of the core. Saved accepted prefixes retain their original observation times.

Owner decisions remain the ADR's deferred lifecycle/resolution, publication boundary, historical completeness/exchange validation, provider-field inventory, operational cache/restart and content-retention contracts. Current-resource changes preserve existing behavior as an implementation baseline and do not declare these deferred policies accepted.

## Validation contracts

Independent `test_transport_independent_guards.py` additionally checks valid current admission/conflicts after physically dropping nine empty legacy stores, and rejects malformed transport/profile references and false capture owners under FK enforcement.

Independent `test_transport_independent_core.py` uses fresh synthetic catalogs with no profiles/originals and checks acquisition, actual producer attribution, inherited fields, missing/null, out-of-order and equal-clock conflicts, incomplete pagination, recorder failures, archive deletion, queries/search, exchange and backup/restore. PR #14/#15 adversarial ownership, JSON-type, clock, transfer and completeness assertions remain. Only their current parser-profile eligibility/capability expectations are superseded with module/version and gate-free behavior tests. Wheel/sdist tests retain Git content verification and historical parser checks and add current module/version assertions.

The [Phase 1 implementation record](phase1-api-original-retirement-implementation.md) records removal/absence tests and scoped residual producers/consumers. Each implementation PR reports only its executed focused/full/package results and base/head SHAs. Historical validation reports are untouched. The remaining legacy parser certificate is regenerated only from successful relevant tests, followed by acceptance without bootstrap overrides.
